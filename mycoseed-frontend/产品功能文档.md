## 一、已实现功能（从代码中读取）

### 1. 用户认证与账户体系

| 功能点 | 描述 | 输入 | 输出 | 关联 API/合约 |
|--------|------|------|------|--------------|
| 手机号登录 | 用户通过手机号 + 短信验证码登录 | phone, code | 登录成功，HttpOnly session cookie 下发给浏览器 | `POST /api/auth/signin` |
| 邮箱登录 | 复用手机号登录逻辑 | email, code | 同上 | 同上 |
| 短信验证码 | 发送 6 位短信验证码到手机 | phone | { result: 'ok' } | `POST /api/auth/send-sms` |
| 开发者免验登录 | 开发/测试环境绕过验证码，选择预设账户直接登录 | userIndex (0/1) | 登录成功 | `POST /api/auth/dev-login` |
| 获取当前用户 | 通过 session cookie 获取已登录用户信息 | 无（依赖 cookie） | 用户完整信息（id, name, phone, email, avatar, evm_chain_address, isSystemAdmin 等） | `GET /api/auth/me` |
| 用户信息更新 | 修改姓名、简介、头像 | name, bio, avatar | { success, message } | `PATCH /api/auth/me` |
| 头像上传 | 上传头像图片文件 | File (multipart/form-data) | { url, hash } | `POST /api/upload/avatar` |
| 用户列表查询 | 获取全平台用户列表（用于任务指定人员、社区添加成员等搜索） | 无 | users[]: {id, name, phone, email} | `GET /api/auth/users` |
| 单个用户查询 | 根据用户 ID 获取详细信息 | userId (UUID) | user 对象含 evm_chain_address | `GET /api/auth/users/:userId` |
| 登出 | 清除服务端 session | 无 | 清除 cookie | `POST /api/auth/logout` |
| 系统管理员角色 | 后端 isSystemAdmin 字段标识；前端控制社区创建等超级权限 | — | — | getMe 返回 isSystemAdmin |

### 4. 任务系统

| 功能点 | 描述 | 输入 | 输出 | 关联 API |
|--------|------|------|------|----------|
| 任务列表 | 按社区过滤展示任务，支持状态分页（全部/可领取/待审核/已完成/已失效） | communityId | Task[] | `GET /api/tasks` |
| 任务详情 | 查看单个任务完整信息（含时间线、参与者列表） | taskId | Task（含 timeline, participantsList） | `GET /api/tasks/:id` |
| 创建任务 | 发布新任务，支持设置标题、描述、积分奖励、报名/提交截止日期、证明配置、参与人数、奖励分配模式、指定人员 | title, description, reward, startDate, deadline, submitDeadline, proofConfig, participantLimit, rewardDistributionMode, submissionInstructions, assignedUserIds, communityId | Task | `POST /api/tasks` |
| 证明配置 | 三种证明方式可选：① 拍照上传（设置张数要求）② GPS 定位（设置精度）③ 文字描述（设置最少字数） | proofConfig: { photo, gps, description } | — | 含在 createTask 请求中 |
| 奖励分配模式 | per_person（每人得 N 积分）或 total（总预算 N 积分，多人平分） | rewardDistributionMode | — | 含在 createTask 请求中 |
| 指定参与人员 | 创建任务时可指定特定用户才能领取（单人任务）或可领取的候选人员列表（多人任务） | assignedUserId / assignedUserIds | — | 含在 createTask 请求中 |
| 领取任务 | 用户领取可领取状态的任务 | taskId, userIdentifier | { success, message } | `PATCH /api/tasks/:id/claim` |
| 提交凭证 | 领取者提交完成证明（文字描述 + 图片文件 + GPS坐标 + 任务感想） | taskId, proof: {description, files[], gps}, receiverRemark | { success, message } | `PATCH /api/tasks/:id/submit` |
| 凭证文件上传 | 上传任务证明图片（支持多文件） | files[], taskId (multipart/form-data) | { files: [{url, hash, name, size, type}] } | `POST /api/upload/proof` |
| 审核通过 | 创建者审核通过并发放奖励（可附审核评语） | taskId, comments | { success, message, data: {claimerId, reward, creatorId} } | `PATCH /api/tasks/:id/approve` |
| 审核驳回 | 支持三种驳回方式：① 允许重新提交（→unsubmit）② 重新发布放回池中（→unclaimed）③ 终止任务（→rejected/已失效） | taskId, reason, rejectOption | { success, message } | `PATCH /api/tasks/:id/reject` |
| 撤回任务 | 发布者撤回尚未被领取的任务，同时返回草稿数据可供重新编辑 | taskId | { success, draft } | `POST /api/tasks/:id/withdraw` |
| 删除任务 | 发布者删除尚未被领取的任务 | taskId | { success, message } | `DELETE /api/tasks/:id` |
| 标记转账完成 | 创建者手动标记链上转账已完成 | taskId | { success, message, data: {transferredAt} } | `PATCH /api/tasks/:id/mark-transfer-completed` |
| 取消转账标记 | 撤销转账完成标记 | taskId | { success, message } | `PATCH /api/tasks/:id/unmark-transfer-completed` |
| 我的任务 | 筛选当前用户发布或领取的所有任务 | — | Task[] | `GET /api/tasks` → 前端过滤 creatorId / claimerId |
| 审核列表 | 获取所有处于 under_review 状态的任务 | — | Task[] | `GET /api/tasks` → 前端过滤 |
| 任务时间线 | 每个任务保留完整状态变更历史（操作者、动作、理由、时间戳） | — | TimelineStatus[] | 读取 task.timeline |
| 分享到社区圈 | 任务完成者可将凭证内容一键分享为社区圈动态（图片可删减、内容可编辑） | content, imageUrls | Post | 通过 /api/communities/:id/posts 发帖 |

| **描述** | 用户可创建一个类似"活动包"的任务包，设定好任务模板后，系统自动按周/月/自定义周期重复发布任务。任务自动上日历、自动生成场次（occurrence），用户按周期领取和完成。本质上是对现有 event kind='pack' 模式的任务化扩展。 |
| **输入** | 任务模板（标题、描述、积分、证明配置等）、重复周期（每周/每月/自定义Cron）、时间范围（起始~结束日期）、每个周期的报名窗口 |
| **输出** | 按周期自动创建的任务实例列表，自动同步到日历视图 |
| **关联合约/API** | `POST /api/community-events/:id/events` (pack type) → 扩展为任务包模式；智能合约为每个周期任务实例创建独立的质押记录 |

### 2. 任务池（悬赏池）

| 项目 | 内容 |
|------|------|
| **描述** | 发布者提交一个总需求和总预算，设定一个大任务的总目标和积分池。其他用户可自行将大任务拆分为子任务并认领。每个子任务独立走完整的领取→提交→审核→发奖流程。总预算被各子任务消耗，直到池子耗尽或关闭。类似"悬赏池"或 Bounty Pool 模式。 |
| **输入** | 总需求描述、总预算积分、子任务拆分规则（由认领者自行拆分或提供模板）、池子截止日期、每人最大可领次数 |
| **输出** | 任务池详情页（池子剩余预算、已拆分子任务列表、进度百分比、参与者贡献排行） |
| **关联合约/API** | 新增 `POST /api/task-pools` 创建池子、`POST /api/task-pools/:id/subtasks` 认领拆分；智能合约需支持池子质押与按子任务解锁放款 |
